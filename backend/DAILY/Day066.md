## 一、今日产出

### 1. 决策：LLM 提供商改为 DeepSeek（ADR 0021）

* 路线图 Phase 4 原计划 OpenAI API；经确认改为 **DeepSeek**（OpenAI 兼容 Chat Completions）。
* 新增 [ADR 0021](../docs/decision-log/0021-deepseek-llm-provider.md)：DeepSeek 提供商、RestClient 原生 HTTP（零新增 Maven 依赖）、opt-in 启用策略、密钥 SSOT（根目录 `.env`）。

### 2. 后端代码（`dev.reboot` 新增 14 个类）

| 组件 | 位置 | 说明 |
|------|------|------|
| `DeepSeekProperties` | `config/` | `deepseek.*` 配置属性（enabled/base-url/api-key/model/timeout/max-tokens/temperature） |
| `DeepSeekConfig` | `config/` | RestClient Bean + 配置属性注册 |
| `DeepSeekClient` | `client/` | `/chat/completions` 调用；未启用/缺 Key/上游错误统一 503 |
| `AiService` | `service/` | 文本补全 + 告警摘要 + 设备健康诊断；JSON 输出解析 + 站点作用域 |
| `AiController` | `controller/` | `POST /api/ai/chat`、`POST /api/ai/alarms/{id}/summary`、`POST /api/ai/devices/{id}/diagnose` |
| `dto/ai/*`（9 个） | `dto/ai/` | DeepSeek 请求/响应、token usage、AI 业务 DTO |

### 3. 配置与环境变量

* `application.yml` 新增 `deepseek.*`；默认 `DEEPSEEK_ENABLED=false`，不配置 Key 不影响核心服务启动；
* `application-test.yml` 新增隔离占位值（不读 `.env`）；
* `.env.example` 新增 `DEEPSEEK_ENABLED / DEEPSEEK_API_KEY / DEEPSEEK_BASE_URL / DEEPSEEK_MODEL / DEEPSEEK_TIMEOUT_SECONDS / DEEPSEEK_MAX_TOKENS`；
* `ErrorCode` 新增 `SERVICE_UNAVAILABLE(503)`，`/api/ai/*` 未启用/缺 Key/上游异常统一返回 503。

### 4. 测试

* `DeepSeekClientTest`：MockRestServiceServer 验证 Authorization 请求头、响应解析（含 usage）、禁用/缺 Key/上游 401 → 503；
* `AiServiceTest`：system/user 消息编排、token 用量透传、结构化 JSON 解析（含 Markdown fence 剥离与纯文本 fallback）、站点作用域 403 阻断（不调用上游）。
