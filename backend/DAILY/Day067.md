## 一、交付范围

### 1. Spring AI ChatClient 抽象（ADR 0022）

| 项 | 交付 |
|----|------|
| 依赖 | `backend/pom.xml` 新增 `spring-ai-starter-model-openai:1.0.3`（与 Spring Boot 3.5.0 对齐，显式锁版本） |
| Bean | `DeepSeekConfig` 新增 `OpenAiApi`（baseUrl=DeepSeek）+ `OpenAiChatModel`（默认 model/temp/maxTokens + `response_format=json_object`）+ `ChatClient` |
| 配置 SSOT | 仍为 `DeepSeekProperties`（`deepseek.*`，dev 读根目录 `.env`，ADR 0015）；不使用 `spring.ai.openai.*` 双源 |
| 业务改造 | `AiService.summarizeAlarm` / `diagnoseDevice` 改用 `PromptTemplate` 占位符渲染 + `ChatClient.prompt().system().user().call().content()`；通用 `chat()` 保留 `DeepSeekClient` 协议层（token 用量/自定义模型/503 语义） |
| 启用校验 | `DeepSeekClient.ensureAvailable()` 改为 public，ChatClient 路径复用同一 opt-in/Key 校验 |
| 自动配置 | Chat 自动配置由显式 Bean 优先接管（`@ConditionalOnMissingBean`）；Embedding/Image/Audio/Moderation 等 5 个未启用能力在 `application.yml` / `application-test.yml` 统一 exclude，避免缺 `spring.ai.openai.api-key` 启动失败 |

### 2. 前端两个最小 AI 入口

| 入口 | 实现 |
|------|------|
| 告警列表「AI 摘要」 | `AlarmList.vue` 行操作新增按钮 → `POST /api/ai/alarms/{id}/summary` → Dialog 展示 priority/summary/可能原因/建议动作；行内 loading + 错误 Alert |
| 设备详情「AI 健康诊断」 | `DeviceDetail.vue` 新增诊断卡片 → `POST /api/ai/devices/{id}/diagnose` → 展示 healthLevel/summary/issues/建议动作；loading + 错误 Alert |
| API 封装 | `frontend/src/api/index.js` 新增 `aiApi`（AI 端点统一 60s 超时，兼容模型慢响应） |

### 3. TD-028 治理（AI 操作日志 + Flyway V9）

| 项 | 交付 |
|----|------|
| Flyway V9 | `V9__ai_operation_log_types.sql`：`chk_operation_type` 扩展 `CHAT/SUMMARY/DIAGNOSE`，`chk_target_type` 扩展 `AI`；H2 test schema 同步 |
| 注解能力 | `OperationLog` 新增 `targetIdArg`，`OperationLogAspect.resolveTargetId` 支持从方法参数取 targetId |
| 端点埋点 | `AiController` 三端点补 `@OperationLog`：`CHAT/AI`、`SUMMARY/AI`（targetIdArg=0）、`DIAGNOSE/AI`（targetIdArg=0） |
| 文档 | `0012-database-changelog.md` V9 行、`sql/README.md`、`TECH-DEBT.md` TD-028 移入已解决 |
