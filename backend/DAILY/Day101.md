## 三、ELK 评估（路线图「可选」项 — 结论：本期不启用）

| 维度 | 评估 |
|------|------|
| 必要性 | 当前单实例 backend，文件滚动日志（14 天）+ traceId grep 已满足排障；无集中日志诉求 |
| 资源 | ES 8.17 单机 ~2GB RAM + Logstash + Kibana，本机负担显著（现跑 5 容器） |
| 观测重叠 | Day 100 Prometheus 已覆盖指标观测；日志检索需求尚未出现（无多服务聚合场景） |
| 备选 | 若 Day 104 完整编排启用：①轻量路径 = logstash-logback-encoder 直发 JSON → ES（跳过 Logstash）或 Filebeat 采集；②更轻候选 = Grafana Loki（与已有 Prometheus 生态同栈） |

**触发条件**（满足其一再评估）：多实例部署需集中日志；按 traceId 聚合分析超出文件 grep 能力；接入第 2+ 个微服务。ES 8.17 维持 compose 锁定不启动，无架构变更故不新增 ADR。

## 四、踩坑

1. **`LevelFilter` 包名**：`ch.qos.logback.core.filter.LevelFilter` 是幻觉类名（ClassNotFoundException），正确为 **`ch.qos.logback.classic.filter.LevelFilter`**——配置错误导致 Boot fail-fast（启动即抛 Logback configuration error），靠临时实例真实启动才发现；教训：logback XML 不参与编译，必须以真实启动验证。
2. **临时实例 MQTT fail-fast**：8081 验证实例与用户常驻 8080 后端互抢 Paho clientId（`iah-backend-mqtt`）→ MqttException 启动失败。解法 `MQTT_ENABLED=false`（OS env 优先级高于 .env，符合 ADR 0015 §8.2）——验证日志/traceId 与 MQTT 无关，干净绕开。
3. **`@Component` 遗漏**：TraceIdFilter 初版漏标 `@Component` → 6 个 @SpringBootTest 上下文全挂（WebMvcConfig 构造器注入无 Bean）。修复后 363/363。与 Day 100「加顶级键先 grep」同类：**新 Filter 进 WebMvcConfig 构造器 = 必须是 Bean**。
