## 三、关键发现

1. **MinIO 镜像源变更（新环境坑位）**：compose 锁定的 `minio/minio:RELEASE.2025-09-07T16-13-09Z`
   在 Docker Hub 已无法拉取（pull access denied）——MinIO 2025-09 起清除 Hub 社区镜像 tag；
   本地 `latest` 经 `--version` 核实恰为同一 RELEASE（当年以 latest 拉取）。
   本日实测方案：本地 `docker tag` 重打（同一镜像字节，纯本地别名）；**新环境部署需自 quay.io
   获取或离线导入**，已记入 Baseline V1.6 审计行。quay.io 匿名 API 也要求认证，未深究。
2. **bind-mount 配置变更不会触发容器重建**：`prometheus.yml` 内容更新后 `docker compose up -d`
   判定服务定义未变 → "Running" 直接跳过；必须 `docker compose restart prometheus` 才加载新配置。
   （「配置文件挂载 ≠ 服务定义变更」，upgrade 流程要注意）
3. **compose 空 env 与 Spring 占位符**：`${VAR:-}` 会把**存在但为空**的变量注入容器，
   Spring `${VAR:50}` 视为已存在 → 解析为空串导致类型转换失败。因此容器侧默认值
   （如 `RATE_LIMIT_PERMITS: ${RATE_LIMIT_PERMITS:-50}`）必须与 application.yml 默认对齐，
   不能注入空串。
4. **双 backend 实例并存的正确姿势**：MQTT clientId 必须不同（否则 EMQX 互踢，Day 101 已踩）；
   RabbitMQ 消费 work-queue 分摊、MQTT ingest 靠 Redis SETNX 幂等去重（Day 96 设计在双实例下
   自然生效）——但 SSE 会话/AI 限流桶仍 per-JVM（Day 91 P1-2 遗留，多实例生产化前置）。

## 四、踩坑

1. **测试类漏 import 直接写完整跑**：`GlobalExceptionHandlerTest` 引用 `ApiResponse` 没加 import，
   首轮全量测试编译失败（BUILD FAILURE 4.6s 即暴露）——补齐后 375/375。教训照旧：
   新文件先让编译器说话，再谈集成。
2. **Docker Hub 瞬时拉取失败**：`eclipse-temurin:25-jre-alpine` 首拉 i/o timeout，
   原样重试即成功——网络抖动别急着改配置，先重试一次。
3. **容器内构建慢**：BuildKit 缓存 0B 时 `dependency:go-offline` 全量下载约 4-5 分钟；
   首次构建耐心等待即可，二次构建吃缓存明显加快。
