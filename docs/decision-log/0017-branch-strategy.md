# Decision 0017: Git 分支策略（main 发布线 + 分支开发）

| 属性 | 值 |
|------|-----|
| **状态** | ✅ 已采纳 |
| **决策日期** | 2026-08-17 |
| **决策者** | hula0710 + AI 助手 |
| **关联** | AGENTS.md §4.4 / runbook / GitHub 分支保护 |

---

## 1. 背景

项目此前所有提交（含 2026-08-16/17 的 ADR 0015/0016 修复）均**直接推入 main**，
main 同时充当"开发线"与"发布线"：

- 无 review gate、无分支隔离，副本部署直接跟随 main HEAD 漂移；
- 遗留分支腐化：`hula0710`（领先 89/落后 28）、`hula0710-backup`（仅本地）、
  `codex/phase-3a`（已合并未删除）；
- 标签稀疏：`v2.1.0` 之后 9 个提交无任何发布锚点。

## 2. 决策（轻量主线策略，不引入 Git Flow 重流程）

| 原则 | 规则 |
|------|------|
| **main = 唯一发布线** | 永远已验收、可部署；禁止直推（GitHub 分支保护 + AGENTS.md 纪律双保险） |
| **日常开发走分支** | `feat/*` / `fix/*` / `docs/*` / `chore/*` / `ai/*` |
| **合并流程** | 分支自测（构建 + 89 测试 + 前端 build）→ push → PR 自审 → 合并 → 删分支 |
| **发布 = tag** | 验收态打 `v2.x.y` + 审计报告；副本/部署锁定 tag |
| **分支卫生** | 历史分支先打 `archive/*` tag 再删除（零丢失） |

## 3. 备选方案（未采纳）

| 方案 | 未采纳原因 |
|------|------------|
| Git Flow（main + develop + release/*） | solo + AI 协作场景过重，develop 与 main 长期平行增加合并负担 |
| 维持现状（全部直推 main） | 本次决策要解决的问题本身 |
| Trunk-based 严格模式（短生命周期分支 + CI 门禁） | 依赖 CI 状态检查；当前无 CI，待 Phase 4 前补充 |

## 4. 执行记录

- 2026-08-17：`v2.2.0` 打标（含 ADR 0015/0016 + 跨平台交接修复）；遗留分支归档为
  `archive/phase-3a` / `archive/hula0710` / `archive/hula0710-backup` 后删除；
- AGENTS.md §4.4 固化纪律；GitHub 分支保护（Require PR + Block force push）由人工在网页开启。

## 5. 影响

- 副本/部署行为可预期：从 tag 拉取，不再吃开发中半成品；
- AI 会话必须建分支 → 审计留痕、可回滚、可并行；
- 例外：治理类元变更（AGENTS.md / ADR 自身）允许 bootstrap 直推并标注。
