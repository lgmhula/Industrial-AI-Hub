## 二、需要你（人工）完成的三件事

1. **屏幕录制**（AI 无法录屏）：macOS 用 QuickTime Player（文件 → 新建屏幕录制）或 OBS；按下方分镜逐幕操作 + 念台词；建议分幕录 9 个片段，剪辑时拼接（比一镜到底容易重录）。
2. **【可选·A 硬件版】真机特写镜头**：ESP32 上电后自动重连（WiFi→EMQX→被后端订阅），无需重新烧录；手机竖拍两个特写——① 对 DHT22 哈气（湿度→100% 触发 OVER_HUMIDITY）；② 继电器吸合（蓝色 LED 亮 / 触点咔哒）。拍完传电脑，剪辑时插入分镜 3。
3. **剪辑拼接 + 导出**：1080p / 30fps / MP4；幕与幕之间用硬切即可；片头片尾可用 README 页面截图淡入淡出。

> **如果不想接硬件**：全程走 B 路径（模拟器），视频同样完整——分镜 3-B 用终端跑模拟器 + 前端实时曲线/报警弹出作为「闭环证据」，依然成立。

### 分镜 3｜数据闭环：硬件版（1:30-3:00，90s）【A/B 二选一】

#### 3-A 硬件版（含真机特写插入）

- **画面 1**（15s）：EMQX Dashboard（http://localhost:18083，admin 登录）→ 监控 → 客户端列表，指出 ESP32 的 clientId 在线
- **画面 2**（30s）：前端设备详情页 → 选择 TEMP 设备 → 实时数据曲线滚动
- **插入**（20s）：**手机特写**——对 DHT22 哈气 → 切回前端报警列表弹出 OVER_HUMIDITY → **继电器吸合特写**
- **画面 3**（25s）：报警列表页：新报警出现、状态未恢复→点击「确认」
- **台词**：
  > 「这是真实的 ESP32-S3 和 DHT22，通过 MQTT QoS1 每 2 秒上报一次。我现在对着传感器哈气——湿度瞬间到 100%，超过阈值，后端规则引擎立刻生成报警，同时通过下行主题让继电器吸合 3 秒作为联动响应。停止哈气，数据回落，报警进入待处理状态，我在前端把它确认掉。」
- **检查点**：哈气 → 报警弹出 ≤ 5s；继电器动作有特写帧

#### 3-B 无硬件版（模拟器）

- **画面 1**（20s）：终端跑分镜一节的模拟器命令，展示 publish 日志滚动（`[pub] TEMP-001 ...`）
- **画面 2**（35s）：前端设备详情 → TEMP-001 → 曲线实时增长（对照终端节奏）；执行 SQL 或前端展示 `device_data` 新增行
- **画面 3**（35s）：报警列表：模拟器尖峰触发的 OVER_TEMP 报警（若 5 分钟内无尖峰，手动把阈值台词带过——「阈值 40°C，模拟器状态机会随机进入尖峰状态」）；若无报警可临时重启一次模拟器直到尖峰出现
- **台词**：
  > 「这台 Java 模拟 PLC 按照和真实 ESP32 完全相同的契约上报——同一条主题、同一个 payload 格式、同一套后端消费逻辑。后端不区分数据来自真机还是模拟器：Redis 幂等去重、落库、判警全链路一致。曲线在实时增长，一旦温度越过 40 度阈值，报警会自动生成。」
- **检查点**：前端曲线随模拟器节奏增长；报警落库可见

### 分镜 4｜报警工作流 + AI 摘要（3:00-4:00，60s）

- **画面**：报警列表 → 选中一条 → 点「AI 摘要」→ Dialog 里 shimmer 骨架屏 → 结构化摘要（优先级徽章 + 处置建议）出现
- **台词**：
  > 「每一条报警都可以让大模型生成处置摘要。后端把报警上下文组装成 Prompt 发给 DeepSeek，返回结构化的优先级和建议，前端用骨架屏兜住加载状态。这是 5 个 AI 业务价值里的第一个。」
- **备选**（DeepSeek 未启用时）：现场点 AI 摘要 → 展示 503 降级 JSON → 「AI 是 opt-in 的，未启用时优雅降级而不是报错崩页面——这也是设计的一部分」
- **检查点**：摘要内容含优先级/建议两段

### 分镜 5｜Agent 巡检日报 + SSE 推送（4:00-5:00，60s）

- **台词**：
