## 二、已解决的关键问题

### B1: Maven Wrapper 构建链路修复

**问题**: HEAD 版 `mvnw` 脚本硬编码本机路径 `/Users/air/Program/apache-maven-3.9.6`，下载依赖 `curl` 但 Alpine 基镜像无 curl/wget，导致干净 checkout 的 `docker build` 在 Step 6 失败 (exit 127)。

**修复**:
- 替换为官方 Apache Maven Wrapper 3.3.4 完整脚本
- 下载策略: wget → curl → Java fallback (编译 Downloader.java 运行下载)
- 预置 `maven-wrapper.jar` (63KB)
- `mvnw` + `mvnw.cmd` 均已提交至 git

**验证**: `git archive HEAD` → 干净 checkout → `docker build` 成功，镜像生成 exit 0。

### B2: 基础设施运行时数据 Git 隔离

**问题**: 232 个运行时数据文件被 git 跟踪 (elasticsearch/_state、elasticsearch/nodes、minio/.minio.sys、nacos/derby-data、nacos/protocol/raft)，运行 compose 后产生 ~200 处 git 变更，clone 者会拿到损坏的半成品状态。

**修复**:
- `git rm --cached` 清除 elasticsearch/minio/nacos 全部运行时数据
- `.gitignore` 新增: `elasticsearch/`、`minio/`、`nacos/`、`rabbitmq/`
- 配置文件正确保留: MySQL cnf (6 个) + Redis conf (3 个)

**验证**: `git ls-files` 确认 ES/MinIO/Nacos 跟踪数为 0；compose 运行后 `git status` 清洁。

## 三、遗留风险 (WARNING，不阻断发布)

以下问题经审计确认不阻断 V2.1 发布，延后至后续迭代处理：

| # | 风险项 | 影响 | 建议处理时机 |
|---|--------|------|-------------|
| 1 | **RabbitMQ mnesia 数据 38 文件残留** — `rabbitmq/mnesia/rabbit@12166dfce31d/` 仍被 git 跟踪 | clone 者获得容器特定 mnesia 数据；`.gitignore` 已阻止新增 | Phase 3 RabbitMQ 接入时 `git rm --cached` |
| 2 | **RabbitMQ `.erlang.cookie` 权限 0644** — RabbitMQ 4.0 要求 600，bind-mount 导致权限破坏，容器重启循环 | RabbitMQ 不可用（backend 无 amqp 依赖，不影响应用） | Phase 3 RabbitMQ 接入时修复挂载策略 |
| 3 | **JwtUtils prod fail-fast 不完整** — env 缺失 JWT_SECRET 时降级为硬编码测试密钥 | 生产环境密钥可能意外降级 | Phase 3 启动前修复 |
| 4 | **application-test.yml JWT_SECRET 死配置** — YAML 属性不经过 `System.getenv()`，test profile 下实际仍走 fallback | 测试环境密钥隔离不完整 | Phase 3 启动前修复 |
| 5 | **API-Reference 幽灵端点** — 文档列出 `GET /api/alarms/all`，实际 AlarmController 无此端点 (5 个) | API 文档与代码不一致 | 文档同步 sprint |
| 6 | **README badge 滞后** — 版本徽章 `v1.0-alpha`、状态行 "Hotfix 中" | 版本标识不准确 | 文档同步 sprint |
| 7 | **compose 无 profiles** — README 的 `docker compose --profile core` 指令无效，实际启动全部 13 服务 | 开发者意外启动重型服务 | Phase 3 或文档同步 |
